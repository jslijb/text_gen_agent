## sieve 抓取 API 集成（用户批准的操作流程，未提交、留工作区审阅）

### 做了什么
- 配置：`settings.py` 加 `SIEVE_BASE_URL` / `SIEVE_API_KEY` / `SIEVE_FILES_DIR`；
  新增 `backend/.env.example`（占位，密钥仍只在 `backend/.env`）
- HTTP 客户端：`app/services/sieve_client.py`（复用项目已有的 httpx，没有引入新客户端）
  - 401/402/404/409/429 → 各自异常的映射；`refused` 终态带 `refusal.code`
  - **创建 run 超时不重试**（无幂等键、被接受即扣费），只有 429/5xx 重试
  - 轮询 5s 起、×1.5 退避到 30s；`queued` 当 running（否则刚创建就判未知状态）
  - 追问等 `done` **且 turns 推进**，否则读到上一轮答案
- 台账：`app/models/sieve.py`（表 `sieve_runs`，`baseline_turns` 存追问基线）
- 任务：`app/tasks/sieve_tasks.py` —— 202 拿到 session_id **先单独 commit 再轮询**；
  单次轮询预算 1500s（celery 硬超时 1800s），用尽留 running；
  beat `resume_pending_sieve_runs`（每 5 分钟）接力 → 这就是"崩溃恢复而不是重开 run"的落点
- 接口：`/api/v1/sieve/{status,runs,runs/{id},runs/{id}/messages,credits}`；
  未配置 key 时 503，其余功能不受影响
- 登录脚本：`backend/scripts/sieve_device_login.py`（支持 `--print-only` / `--from-state` / `--set-key`）
- 文档：CLAUDE.md 新增"sieve 抓取 API 集成"章节；README 能力表 + env 说明

- `POST https://scrape.usesieve.com/api/auth/device/code` 稳定 **401 `{"error":"unauthorized"}`**：
  换 Origin/Referer/UA、换 `queued`/`device_authorization` 等 11 种路径写法、换 api.usesieve.com 都一样

  其余路径（**包括不存在的**）一律先 401 → 鉴权门在路由之前，说明文档里的设备登录入口在当前部署下不可达
