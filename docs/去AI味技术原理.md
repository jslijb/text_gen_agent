# 去AI味（Humanizer）技术原理

## 一、问题背景

AI 生成的小说文本存在明显的"机器味"特征，容易被 AI 检测工具识别。主要表现为：
- **套话泛滥**："值得注意的是""不仅如此""综上所述"等学术/公文用语
- **句式工整**：每句 20-30 字均匀排列，缺乏长短交替的自然节奏
- **排比堆砌**："有的……有的……还有的……"等模板化结构
- **对话演讲化**：人物说话像念稿，缺乏打断、省略、口语化
- **缺乏细节**：用抽象概括代替具体描写（"他很难过" vs "他把烟头摁灭在手腕上"）

## 二、核心架构

```
原文 → [策略1: 正则替换] → [策略2/3/4: LLM重写] → [AI评分] → [一致性检查] → 输出
```

## 三、四种去AI化策略

### 策略1：Quick（纯正则，无LLM调用）

**原理**：用 26 条正则规则匹配 AI 套话模式，替换为口语化表达。

| AI套话 | 替换为 |
|--------|--------|
| 值得注意的是 | 需要关注的是 |
| 不仅如此 | 而且 |
| 总而言之 | 总之 |
| 毫无疑问 | 肯定 |
| 众所周知 | 大家都知道 |
| 显而易见 | 明摆着 |
| 在当今社会 | 现在 |
| 随着…的发展 | 现在 |
| 发挥了重要作用 | 很关键 |
| 具有重要意义 | 很重要 |
| 他感到非常震惊 | 他愣住了 |
| 她不禁感叹道 | 她叹了口气 |
| 仿佛…一般 | 像 |

**优点**：速度快（<1秒）、零成本、确定性
**缺点**：只能替换已知模式，无法处理深层AI特征

### 策略2：Default（正则 + LLM重写）

**原理**：先执行正则替换，再用 LLM 以"资深作家改写朋友草稿"的角色重写全文。

**LLM Prompt 核心规则（9条铁律）**：
1. **打破工整**：长短句交错，3字短句和50字长句混合
2. **删废话连接词**：删除一切AI套话
3. **加口语词**：插入"啧""呵""嗯""靠"等人味语气词
4. **加具体细节**："他很难过"→"他把烟头摁灭在手腕上，一声不吭"
5. **拆掉排比**：打散模板化排比结构
6. **保留核心剧情**：只改表达方式，不改情节
7. **减少"了"字**：替换"了起来""到了""成了"
8. **对话精简**：砍掉一半对话长度，真人说话短促
9. **直接输出**：不加任何解释说明

**温度**：0.85（较高，增加多样性）

### 策略3：Deep（多语言接力翻译）—— 已弃用

**原理**：中→日→芬→中 翻译链，通过多次翻译打破AI句式模式。

**弃用原因**：翻译腔本身是AI特征，实测分数反而上升。

### 策略4：Recursive（递归释义 + Best-of-N）—— 推荐策略

#### 核心思想

AI文本的本质问题是"过于规整"——用词、句式、节奏都高度可预测。Recursive策略的思路是：**用"改写→评分→选最优"的反馈闭环，像进化算法一样逐轮淘汰AI特征最重的版本，保留最像人写的版本。**

类比：就像老师批改作文，让学生反复修改，每次只保留改得最好的那一版，几轮下来文章就越来越自然。

#### 为什么"递归释义"能去AI味？

**学术依据**：arXiv:2303.11156《Can AI-Generated Text be Reliably Detected?》

该论文的核心发现：
1. **AI文本有统计可检测性**：AI生成的文本在词频分布、句长方差、困惑度（perplexity）等维度与人类文本有系统性差异
2. **释义攻击（Paraphrase Attack）有效**：对AI文本做一次释义改写，就能显著降低检测准确率；多次释义后，检测器几乎失效
3. **检测器本质是分类器**：AI检测器（如GPTZero、DetectGPT）本质上是在做二分类，释义改写会改变文本的统计特征，使其落入"人类"一侧

**递归释义的原理**：
- 每一轮改写都是一次"释义"（paraphrase），会扰动AI文本的统计特征
- 多轮递归相当于多次扰动，AI特征被逐层"稀释"
- 但单次改写可能引入新的AI痕迹（因为改写的还是LLM），所以需要Best-of-N筛选

#### Best-of-N 选择机制

**问题**：LLM改写本身也是AI生成的，可能引入新的AI特征。

**解法**：每轮不只生成1个候选，而是生成N个（默认3个），用AI评分函数挑分数最低的。

**为什么有效**：
- LLM在高温度（0.8~0.9）下生成的文本多样性很高
- N个候选中，至少有1个碰巧更接近人类写作风格的概率很大
- AI评分函数充当"选择压力"，像自然选择一样筛掉AI味重的版本

**温度递增**：3个候选分别用温度0.8、0.85、0.9生成，温度越高输出越随机，增加候选多样性。

#### 全局最优追踪

**问题**：第2轮改写可能比第1轮差（LLM改写不是单调改善的）。

**解法**：维护全局最优（best_overall），跨轮次保留历史最低分候选。

```
第1轮最优(分数45) → 第2轮最优(分数52，比第1轮差) → 第3轮最优(分数38)
                  ↓
              全局最优始终是第1轮的45，直到第3轮的38刷新记录
                  ↓
              最终输出分数38的版本
```

#### 一致性检查：防止改写偏题

**问题**：去AI化改写可能改变核心剧情（人物死了变活了、结局变了）。

**解法**：每个候选必须通过一致性检查才能参与评分。

**两层检查**：
1. **LLM审核**（主）：让LLM对比原文和改写，判断剧情/人物/结局是否一致
2. **关键词比对**（降级）：提取数字、百分比等事实元素，缺失>30%视为不一致

**关键设计**：不提取对话作为关键词——去AI化必然会重新措辞对话，如果对话也算关键词，会导致所有候选都被误判为"不一致"而回滚到原文。

#### 降级容错

- 单轮所有候选生成失败 → 跳过该轮，继续下一轮
- 单个候选一致性检查未通过 → 跳过该候选，评估其他候选
- 所有轮次全部失败 → 返回正则替换后的原文（不返回完全未处理的原文）

#### 完整流程图

```
原文
 ↓
[正则替换] → 替换26种AI套话
 ↓
第1轮 ──→ 候选1(温度0.8) ──→ 一致性? ──→ AI评分
      ──→ 候选2(温度0.85) ──→ 一致性? ──→ AI评分  ──→ 选最低分
      ──→ 候选3(温度0.9) ──→ 一致性? ──→ AI评分
 ↓
第2轮（以第1轮最优为输入，重复上述过程）
 ↓
第3轮（以第2轮最优为输入，重复上述过程）
 ↓
输出：全局最低分版本
```

#### 参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| rounds | 3 | 递归轮次（越多越像人写，但耗时线性增长） |
| n_candidates | 3 | 每轮候选数（越多选择空间越大，但LLM调用数=轮次×候选数） |
| temperature | 0.8~0.9 | 候选生成温度（递增，增加多样性） |

#### LLM调用次数

总调用数 = rounds × n_candidates × (1次改写 + 1次评分 + 1次一致性检查) = 3×3×3 = 27次

实际优化：quick策略的统计评分不调LLM，一致性检查和评分可合并，实际约9-15次。

## 四、AI检测评分机制

### 混合评分公式

```
最终分数 = LLM自评 × 0.7 + 统计特征 × 0.3
```

- **LLM自评**（权重70%）：让LLM以"AI检测器"角色评估文本，输出0-100分
- **统计特征**（权重30%）：纯规则评分，作为LLM不可用时的降级方案

### 统计特征评分维度

| 维度 | 检测方法 | 加分（越高越像AI） |
|------|---------|-------------------|
| 套话命中 | 26条正则匹配 | 每命中+5 |
| 平均句长 | >40字+15，>30字+8 | +8~15 |
| 句长方差 | 方差<20（过于均匀） | +10 |
| 重复字符 | 连续3+相同字符 | 每次+2 |
| 排比结构 | "一、二、三"枚举 | 每次+3 |

基础分30分，上限100分。

## 五、剧情一致性检查

防止去AI化改写偏题，两层防护：

### 第一层：LLM审核（主）
让LLM对比原文和改写，判断核心剧情/人物关系/关键事件/结局是否一致。

### 第二层：关键词比对（降级）
提取数字、百分比等事实性元素，缺失>30%视为不一致。

**关键修复**：不提取引号内对话作为关键词（去AI化必然重新措辞对话，会导致误回滚）。

## 六、实测效果

| 策略 | AI分数变化 | 耗时 | LLM调用 |
|------|-----------|------|---------|
| Quick | 79.9→61.5 | <1s | 0次 |
| Default | 79.9→45.2 | ~30s | 1次 |
| Recursive | 79.9→35.8 | ~90s | 9次 |
